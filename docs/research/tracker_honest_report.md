# Честный полевой инструмент: патчи «не знаю», цепочка замеров, наст

Модуль: `tracker_tool.py` (интерфейс для поисковика). Модель НЕ оптимизирована — послойная
с фиксированными параметрами (k_накоп=0.5, k_ref=0.0264, c=0.136, k_тай=0). Цель — честность.

---

## ЗАДАЧА 1. Патчи «не знаю» (в `estimateAge`)

Правила, применённые к обратному поиску t* = argmin|H_расч(t) − H_obs|:

| Патч | Действие |
|---|---|
| t* > 10 | **«давность неопределима»** (не число) |
| резкий снегопад P>5 при T<−5 за последние 3 дня | **«возможна ошибка из-за уплотнения»** |
| наст в истории (T>0 + P>0 за 30 дней) | **«возможна ошибка, проверьте вручную»** |
| σ > 2 (разброс правдоподобных t, где err ≤ min+1 см) | **диапазон «N1–N2 дней»** вместо числа |
| история погоды < 10 дней | **«недостаточно данных»** |

## ЗАДАЧА 2. Цепочка замеров (в `estimateChain`)

Поисковик вводит **3–5 замеров глубины одного следа в один визит** (по разным точкам следа):
- берётся **МИНИМУМ** (исключает намет/занос);
- разброс (max−min) > 3 см → **«след неравномерный, широкий интервал»**;
- вывод: **«Глубина: минимум X см (разброс Y см)»**;
- затем `estimateAge` по минимуму с датой визита.

## ЗАДАЧА 3. Наст как бинарный признак

- Поисковик отмечает: **«есть наст» / «нет наста»** (щуп стукнулся / прошёл) → режимы
  `crust_mode='yes'/'no'/'auto'` в модели: если наст есть, **оседание слоёв ниже наста остановлено**;
  если нет — всё оседает.
- **Автоопределение даты наста из архива**: `nast_dates()` находит в истории дни (T>0 и P>0), после
  которых наступает день T<0 (оттепель/дождь → заморозка) и возвращает дату. В 2024-25 найдены
  ~2024-12-22 и ~2025-01-03.

---

## Проверка на 2024-25 (134 замера с историей ≥10 дней; 58 свежих 0–2 дня)

| Метрика | ДО (всегда число) | ПОСЛЕ (патчи + 3 исправления) |
|---|---|---|
| recall 0-2 (только числа ≤2) | 0.810 | 0.810 |
| recall 0-2 (вкл. диапазоны, начинающиеся ≤2) | 0.810 | 0.810 |
| «давность неопределима» | 0% | **14%** |
| «недостаточно данных» | 0% | 0% |
| ответ «диапазон» (непрерывный интервал, σ>2, ширина ≤7) | 0% | 3% |
| MAE по уверенным числам | 2.40 дн | 2.33 дн (n=111) |

**Исправления (после ревизии кода):**
1. **age_range** — непрерывный интервал вокруг t* (lo/hi, где err ≤ min+1), а не разрозненное
   множество; **если ширина (hi−lo) > 7 → «неопределима»**, а не «диапазон». Диапазонов стало 3%,
   «неопределима» выросла до 14% (19 строк) — лишние широкие ответы честно отсеяны.
2. **format_estimate** — `nast_date` выводится только при наличии (`if est.get("nast_date")`),
   иначе строка без наста.
3. **forward `crust_mode='yes'`** — дата наста берётся из `nast_dates` (T>0+P>0, затем T<0) и
   `crust_epoch` ставится на эту эпоху, а не на i=0. Влияние режимов наста на recall 0-2:
   `auto` — 0.810; `yes` (щуп стукнулся) — 0.810; `no` (щуп прошёл) — 0.741. С настом больше
   честных «неопределима» (22%) — заморозка оседания расширяет неоднозначность у старых следов.

**Смысл изменений:** категоричных чисел стало меньше (83% vs 100%), но они надёжнее (MAE 2.33);
recall 0-2 не пострадал (0.810); 14% следов честно помечены «неопределима» (в 2 раза больше, чем
только по правилу t*>10) — интервалная неоднозначность теперь тоже отсекается.

**Предупреждения:** «оттепель/дождь в истории» сработало на 80% строк 2024-25 — сезон был
нестабильным (тёплые дни в декабре), поэтому предупреждение в этом сезоне почти всегда; для полевой
практики разумно сузить до последних 7 дней (гипотеза, в коде оставлено по ТЗ — 30 дней).
«Резкий снегопад P>5 при T<−5 за 3 дня» — 0 случаев в 2024-25 (данных нет).

## Честные ограничения
1. **Старые следы (10+ дней)**: обратный поиск по-прежнему может дать уверенное, но неверное число
   (пример: след 19, факт 12 → «≈4 дня»). Патч t*>10 ловит только часть; полное решение невозможно —
   глубина старых следов насыщается. Предупреждение «проверьте вручную» остаётся главной защитой.
2. **Предупреждение об оттепели** срабатывает часто в нестабильные сезоны (80% в 2024-25) — при
   полевой настройке сузить окно до 7 дней.
3. **«Недостаточно данных»** — честный ответ, когда эпохальной погоды нет (февраль–март 2024-25 и т.п.).

## Полевой интерфейс (как пользоваться)
```
estimateChain(сезон, дата_визита, [глубина_1..5], crust_mode='auto'|'yes'|'no')
  -> Глубина: минимум X см (разброс Y см) [+ след неравномерный]
  -> давность ≈ N дней | N1–N2 дней | давность неопределима | недостаточно данных
  [+ предупреждения, + дата наста по архиву]
```
