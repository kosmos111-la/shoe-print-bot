# Шаг 6 (подготовка). Train/test без утечек

Данные: `prep6_report.txt`. Датасет: **`model_dataset.csv`** — 1293 строки, 250 объектов (сезон×след).

## Ключевой факт
`след_id` повторяется между сезонами («След 1..116» в каждом сезоне) — это **разные объекты**.
Сплит и проверка пересечения выполняются строго по **(сезон, след_id)**, никогда по строкам
внутри следа.

## Протокол 1 (основной, рекомендованный): по сезонам
- **TRAIN**: 2022-23 + 2023-24 → **1035 строк / 158 следов**
- **TEST**: 2024-25 → **258 строк / 92 следа**
- Пересечение (сезон×след): **0** ✅
- Баланс классов: TRAIN 285/324/426, TEST 91/77/90 (0-2/3-7/8+) — тест-распределение близко к train.
- ⚠️ Учесть из шага 5: в 2024-25 глубина категории 8+ = 1.7 см (против ~10 в других сезонах) —
  метрики на этом тесте будут занижены; интерпретировать с поправкой.

## Протокол 2 (строже): 2023-24 по длине серий
- TRAIN: 2022-23 + 2023-24 (серия ≥5 дней) → **892 строки / 81 след**
- TEST: 2023-24 (серия ≤4) + 2024-25 → **401 строка / 169 следов**
- Пересечение: **0** ✅ (31 длинный след 2023-24 остаются в train)
- Использовать, если хотим гарантировать, что тест содержит только «недообученные» следы.

## Протокол 3: Cross-validation по сезонам (Leave-One-Season-Out)
| test-сезон | TRAIN | TEST |
|---|---|---|
| 2022-23 | 684 / 199 | 609 / 51 |
| 2023-24 | 867 / 143 | 426 / 107 |
| 2024-25 | 1035 / 158 | 258 / 92 |

Подходит для оценки устойчивости модели; итоговую метрику — усреднить по фолдам.

## Другие источники утечки (закрыты)
1. «След 1» исключён из датасета полностью (81 строка) — референс не обучается (шаг 3);
2. глубина «След 1» не используется как признак (будущее на дату прогноза неизвестно);
3. «суточный» других следов не используется как признак осадков (след-специфичен, шаг 4);
4. признак «место (лес/открытое)» отсутствует в данных — исключён (шаг 5);
5. при обучении с временными признаками помнить: погодные признаки дня — это контекст,
   одинаковый для train/test дат одного сезона; категория (таргет) от погоды дня не зависит.
