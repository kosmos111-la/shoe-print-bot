# Итоговый отчёт: послойная физическая модель давности следа (ЭТАП 8)

Модель интегрирует погоду по **эпохам** (4 в сутки: ночь/утро/день/вечер, по 6 ч), учитывает
порядок событий, наст и дождь. Отчёты этапов: `layered1_report.txt` (эпохи), `layered2_report.txt`
(прямая задача), `layered34_report.txt` (наст и k_тай), `layered5_report.txt` (обратный поиск+интервалы),
`layered7_report.txt` (сравнение с RF/базовой). Код: `epochs.py` (общий модуль).

## Псевдокод модели

**Прямая задача** (H_расч для следа, установленного в день D0, замер в D1):
```
слои = [слой(H0=0.2, born=-1)]          # начальная пухлость следа
наст_эпоха = None
для каждой эпохи e из [D0, D1]:          # ночь, утро, день, вечер
    # наст: Σmax(T,0) за 2 эпохи > 10 ИЛИ (T>0 и P>0)
    если наст_эпоха is None и признак_наста(e): наст_эпоха = e
    # оседание каждого слоя (кроме замороженных под настом):
    для слоя L: если наст_эпоха is None или L.born >= наст_эпоха:
        L.h *= exp(-0.0264 · exp(0.136·T_e) · 0.25)
    # событие:
    если T_e <= 0 и P_e > 0:  слои += [слой(0.5·P_e, born=e)]     # снег
    если T_e >  0 и P_e > 0:  таяние сверху: H -= k_тай·T_e·P_e   # дождь (k_тай=0)
H_расч = Σ L.h
```

**Обратная задача** (возраст по H_obs, архив эпох за 30 дней):
```
для t = 0..30: H_расч(t) = прямая(дата−t, дата)
t* = argmin |H_расч(t) − H_obs|
σ = разброс t* при вариации (H0, k_накоп, k_ref, c)
ответ: возраст = t* ± σ
```

## Параметры (все из данных, без оптимизации)
| параметр | значение | источник |
|---|---|---|
| H0 | 0.20 см | медиана глубины следов возраста 0–2 |
| k_накоп | 0.50 см/мм | медиана ΔH/осадки по 79 коротким снежным событиям |
| k_ref, c | 0.0264 1/день, 0.136 1/°C | калибровка базовой формулы (предыдущий этап) |
| k_тай | **0** | см. ЭТАП 4 — данные не подтверждают дождевое таяние |
| наст | правило включено | улучшает прямую задачу: MAE 2.19 vs 2.31 см |

## Итоги этапов
- **ЭТАП 1 (эпохи)**: в дневнике T и P есть по каждой эпохе. Покрытие: 2022-23 — 52 даты (94%),
  2023-24 — 112 (70%), **2024-25 — только 39 (24%)**. Пример следа: 3 дня → 16 эпох, тип по эпохам
  `- - - С / С С С С / - - - -` (порядок событий виден).
- **ЭТАП 2 (прямая задача, 10 свежих следов 2022-23)**: до оттепели MAE=1.96 см, корреляция **0.963**;
  смещение −1.7 см (k_накоп=0.5 слегка занижает ранний сезон). Фазу таяния (после 27.02) без k_тай не воспроизводит.
- **ЭТАП 3 (наст)**: правило «заморозить слои ниже наста» улучшает модель (crust ON 2.19 vs OFF 2.31 см MAE);
  эмпирически после наст-дней доля падений глубины 51% vs 36% — из-за таяния, сопутствующего насту.
  Правило работает, но слабо.
- **ЭТАП 4 (дождь)**: k_тай подобрано = **0**. Осадки при T=+1..+2 °C в дневнике давали РОСТ глубины
  (мокрый снег), а не таяние; настоящих дождей (T>+2) в данных почти нет. Таяние не откалибровано — сказано явно.
- **ЭТАП 5 (обратный поиск)**:
  - **2024-25 (20 строк с полной эпохальной историей, как раз «20 примеров»): MAE=2.15 дня, медиана 1, ±3: 80%, ±7: 95%**.
  - Возраст 0–2 дня определяется отлично (σ=0, точные попадания); следы 5–12 дней в 2024-25 имеют **одинаковую глубину
    (3.2–3.9 см)** — модель их не различает (t*≈4). Это свойство данных, не модели.
  - 2022-23 (7.1 дн) и 2023-24 (10.3 дн) хуже: там следы старше 30 дней (предел прокрутки) и фазы таяния,
    сбрасывающие глубину — обратный поиск по ним заведомо ошибается.
- **ЭТАП 6 (интервалы)**: параметрический σ узкий (0–1 дн) и **переоценивает уверенность — покрытие факта всего 40%**.
  Практическая неопределённость = эмпирический MAE: интервал t* ± 2 дня (на тесте ±3 дня даёт 80% попаданий).
  Флаги: σ_эфф < 1 «уверенно», σ_эфф > 2 «низкая уверенность» — по эффективному σ (макс. параметрич., 2 дн).
- **ЭТАП 7 (сравнение на 2024-25)**:
  | модель | recall 0-2 (все 178) | recall 0-2 (20 строк с эпохами) | recall 8+ (178) |
  |---|---|---|---|
  | RF | **0.864** | **1.000** | 0.083 |
  | базовая формула | 0.802 | 0.818 | **0.417** |
  | послойная модель | — (нет эпох) | 0.818 | — |
  **Вывод: послойная модель НЕ лучше** — на 20 доступных строках равна базовой формуле (0.818, MAE 2.15 vs 2.00)
  и уступает RF (1.000). Сравнить на всех 178 строках нельзя: эпохальная погода в 2024-25 есть только на 20.
  Преимущество эпох (порядок событий, наст) в тестовом периоде не проявилось — там не было ни оттепелей, ни наста.

## Пример вывода для поисковика
```
Глубина 1.6 см, история: T ≈ -5°C, осадки 2 мм.
Возраст: 1 день (интервал [1–2], σ=0.5) — уверенно.          ← след 28, факт 3 дня (промах на 2)
Глубина 3.3 см, T ≈ -5°C, осадки ~10 мм за период.
Возраст: 4 дня (интервал [3–5], σ=1.0) — средняя уверенность. ← след 23, факт 8 дней
```
Шаблон из задания: «Глубина 3 см, T: −5°C, осадки 2 мм → Возраст: 3.4–5.1 дня (уверенность 0.8)» — модель выдаёт
именно такой интервал, но с оговоркой: узкие интервалы на этих данных часто переоценивают точность.

## Ограничения (сказано явно)
1. **Нет эпохальной погоды в 2024-25** (39/161 дат; только 20 строк теста имеют полную историю 30 дней) —
   главное ограничение для валидации послойной модели.
2. **Таяние не откалибровано** (k_тай=0): осадки при T=+1..+2 в дневнике вели к росту глубины (мокрый снег);
   настоящих дождей мало; обвал глубины 27.02 (15.6→0.4) — в эталонном «След 1», свежие следы так не падали.
3. **Обратный поиск ограничен 30 днями** (как задано); следы старше 30 дней и следы после оттепели
   (глубина сброшена) не инвертируются.
4. **2024-25 ранний сезон**: следы 5–12 дней имеют почти одинаковую глубину — разделить их не может ни одна модель.
5. Лес (ветер), плотность снега не учтены; «След 1» — эталон покрова, не свежий след.

## Рекомендация
- Для калькулятора сейчас честнее **базовая формула** (проще, на доступных строках тот же результат 0.818)
  или **RF** (выше recall 0-2: 0.864 vs 0.818–0.802); послойная модель даёт физику и порядок событий, но
  на этих данных преимущества не показала.
- Дособрать: **эпохальную погоду на все даты** (главное!), периоды с оттепелью→снег (чтобы проявился порядок
  событий и наст), следы 5–12 дней в 2024-25 (сейчас неразличимы), плотность/место.
- Послойную модель держать как развилку: при появлении эпохальных данных с событиями (наст, оттепель) —
  перекалибровать k_тай и перепроверить на полном тесте.
